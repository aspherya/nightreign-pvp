# Traps we already hit

Read when you touch the area named in a bullet, or before debugging something odd. One owner doc for traps; add new ones here (date + what + the rule), not in STATUS.

- **Nucleus `dlllist.txt` must not end with a newline.** It makes Nucleus fail with "WaitForSingleObject failed 258". The deploy script writes it correctly; never edit it by hand.
- **Under Nucleus, keys reach a window only when it has focus** (END unlocks input). Use the console instead: `nrcon --all <cmd>` reaches every instance.
- **Nucleus deletes its instance folders on close.** Logs go to `dist\nucleus-logs\` for that reason.
- **Nucleus does not load our game-data package when it starts the game through Seamless Co-op's launcher** (the plain deploy):
  no no-boss nights, vanilla hawk route. `deploy-nucleus.ps1 -Me3` (start through our launcher / me3) works for window 1 only:
  window 2 stops on ColdLoader "appid not found" (2026-10-23, cause UNKNOWN). Use the plain deploy. Event-script features are tested solo with `scripts\launch.ps1`; under Nucleus use the dev console
  (`flag`, `clock`) instead.
- **Never run the scanner or any tool against the normal game.** Steam launch = vanilla with anti-cheat. Mods only through Nucleus, `nrpvp_launcher.exe`, or `scripts\launch.ps1`.
- **Never touch the vanilla saves** (`%APPDATA%\Nightreign\<id>\NR0000.sl2*`).
- **Player ids change between the lobby and the expedition** (run 21: joiners were `0x6003`/`0x6004` in the lobby, `0x6002`/`0x6003` in
  the expedition). Teams are only meaningful once the expedition has loaded; do not decide or show teams from lobby ids.
- **Addresses change every launch and every area load.** A value found by the scanner is only good for that run; the mod must reach it through the player object (see `re/MEMORY_MAP.md`). A scanner left watching a fixed address after a restart is looking at the wrong memory: stop it.
- **Double-check offsets before any write.** On 2026-10-12 a test wrote to `+0x728/+0x72C` instead of `+0x718/+0x71C` by mistake (no lasting effect).
- **Setting health to 0 does not kill** in a multiplayer session; it downs. Death is the bleed-out clock reaching 0.
- **Elden Ring layouts are hints only.** Several were wrong in Nightreign (list in `re/MEMORY_MAP.md` §9).
- **No `VirtualQuery`-guarded reads on the main loop.** They made each pass take 2–3 s in an expedition (run 15). Use `mem::read` or
  `RegionCache::direct()` there (the guarded `RegionCache::new()` is test-only since R5). The heartbeat line shows the pass time.
- **Only a lobby the game makes can be joined.** Our own `CreateLobby(Public, 6)` gets adopted by Seamless Co-op but joiners' games
  leave it at once, and a direct `JoinLobby` gives Steam membership without the game session (FS-MM2). Steam lobby membership is not
  presence: ALL PRESENT also needs the host's ChrSet to hold the players.
- **`RegionCache::readable_len` is a `VirtualQuery` even on the direct cache.** `flags::locate` used it; 12 flag reads per tick made the
  main loop take 0.6 s (solo) to 2.4 s (Nucleus) per pass (2026-10-23). Read flags only through the fixed `locate` (plain copies).
- **Nucleus has the vanilla night**: minions, the wipe check (both down = game over for both) and the night freeze (a knocked player
  inside the circle never bleeds out). Never put both players on team 6 at night there (1182 counts them out → instant wipe); use
  console `god 1` on the knocking player instead. `clock end` on a fresh day kills everyone outside the closed circle: use
  `clock circle` and walk in.
- **`mm_lobby_trace` (and `ui_text_trace`, `ui_menu_trace`, `ui_c1_proto`) take all four debug registers** and bypass `hwbp.rs`; config turns the `hwbp` users off while one is on. Quiet invite uses hwbp slots 0 and 1.
- **Sonnet agents can be cut off by usage limits mid-task.** Check `cargo build` and `git status` before trusting the tree; the task card says what was intended.
- **Hardware breakpoints are a shared budget of four** (player build: `menuflow` holds slots 2 and 3 for the whole session and never clears them, so only slots 0 and 1 are free in an expedition; `reviveblock` takes up to 2 while someone is downed, the deathhold takes 1 for the hold and, at the release, 1 for gate A and after 2 s 1 more for gate B. It works only because downed, dead and releasing never overlap. A claim/release API with owner ids is planned after the FS-M59 logs; `hwbp::set` silently overwrites whoever holds a slot) (2026-10-24): hold, gate, reviveblock, menu/matchmaking and, in dev, the puppets (three) all draw on them (`hwbp.rs`). The M5-9 release failed with puppets present because the start breakpoint stayed armed while the gate wanted a slot (fixed). Any new feature that needs a breakpoint states how many slots it holds at peak and frees them when done.
- **Offline solo carries SpEffect 6999500** (a revive item on the script's list), so the die-at-once rule is OFF there; a death there needs `flag 10007420 1` (SpEffect 102130, die at once) first; the RW scenarios do that.
- **Console tails are unreliable evidence in scenarios:** `log 300` returns the last 300 lines, and event bursts (flag watch) push lines out; turn `ui_flag_watch = false` in scenarios and, when possible, assert on `night_status` / state commands instead of log text.
- **One swing does not down every puppet** (position and facing drift after a morning move): down puppets with `puppet_hp <slot> 0`.
- **`nro` needs `nro desk` in a normal terminal for keys and screenshots** (an agent can start it in the Terminal panel); the game's quit crashes, so runs end with `nro stop`.
- **One-PC scenarios need the desktop** (2026-10-24): a Windows screensaver or lock screen makes every screenshot black and every key land nowhere (`nro` says "the picture is black"; `title_to_world` times out after 300 s). Check `tasklist | findstr scrnsave`, kill `scrnsave.scr`, and keep the display awake with `scripts\keep-display-on.ps1` in a Terminal tab (an agent session does this too: `request_keep_awake`). `scripts\idle-seconds.ps1` says how long the user has not touched the PC; the scenarios inject keys and clicks into the game window, so run them while the user is away.
- **The Number of Players setting is a ring of three values the game keeps between runs** (and a friend session leaves it on Duo / Trio / "Up to 6"): the offline Commence then says "Matchmaking failed". `nro`'s `to_expedition` now tries all three (F2 = Matchmaking Settings tab, RIGHT steps the ring).
- **A running `nro desk` locks `target\release\nro.exe`**: `scripts\build.ps1` then fails at the link step. Use `scripts\build-mod.ps1` (nrpvp.dll + nrcon.exe only), or stop the desk tab first. Simpler: run the desk from a copy (`copy target\release\nro.exe runs\nro-desk.exe`, then `runs\nro-desk.exe desk`).
- **`nro launch --emulated` from an agent's sandboxed Bash fails P-module** (2026-10-27): that sandbox cannot open the game process (`OpenProcess` fails, `DebugActiveProcess` error 87), so `nro` saw "alive=false, 0 modules" and gave up while the game ran on. Run `nro` from the PowerShell tool or a Terminal tab. `nro` now waits for the real exit code instead of `!alive`.
- **Windows reuses pids** (2026-10-27): a stale `session.json` pid belonged to a `powershell.exe` and `nro launch` said "a session is already running". `live_pid` and `stop` now check the image name (`nightreign.exe`, `me3*`) before trusting or killing a pid.
- **A run killed inside an expedition leaves an "online?" dialog at the next title** (2026-10-27, `mi-queue`): "Unable to restore current session due to lack of internet connectivity. Switch to online mode to restore current session?" with **OK focused**; ENTER means "go online". `title_to_world` screenshots before every title key and clicks CANCEL (offline) when it sees the dialog's two button frames; never answer a title dialog with ENTER blindly.
- **Emulated runs: never `mm_join_auto` with `link`** (2026-10-27): the joiner's `steam://joinlobby` goes to the Windows shell, which starts the real Steam client when it is closed. nro forces `"invite"` and preflight P7 refuses `link` on emulated instances. Also keep `mm_host_create = false` (the dev dist toml had it on: the mod's own lobby is never joined, MATCHMAKING §8).
- **The first key into a game window that was in the back is sometimes lost** (2026-10-27): F at the table did nothing once. Macros check a state (the `menu` word of `pos`) and retry instead of assuming a key landed.
- **The table prompt needs the heading, not only the spot**: at the Commence spot facing away there is no "F: Commence expedition". `tp x y z yaw` sets both; Q (not Esc) closes the expedition menu, and in the plain world Q is the harmless lock-on while Esc opens the pause menu.
- **A whole-process memory scan takes about a minute** (9-12 GiB, `game/memscan.rs`) and a failed `ReadProcessMemory` page is skipped; the scan runs on its own thread and costs the main loop 0 ms (heartbeat). Never put it on the main loop. Results are heap addresses: they change every launch.
- **A mob death needs about 14 s from 0 HP to standing** (`defeat-mob`, 2026-10-24): the "dead for this long = out of the match" timer (`OUT_DEAD_MS`) must stay well above it.
- **HP reaches 0 up to 100 ms before the downed byte is set** (Nucleus 3-player run 2026-10-25): "HP 0 and not downed" is not a death. `night_match` waits `DEAD_DEBOUNCE_MS` (800 ms); without it a player was judged defeated at the hit and dragged to the killer while still downed.
- **Nucleus runs have no event files**: the win / lose banners (our events 4000 / 4010) do not play; the mod writes the game's own end flags 7000 / 7001 after 1.5 s (`our flag … still ON`). Not a bug. Keep `scriptsuild-mod.ps1` and a running `nrcon` loop apart: a watcher polling `dist
rcon.exe` locks it.

- **With two game windows, the first key after the focus moves is lost** (`mi-rw9-markers`, 2026-10-27): `Q; M` meant to close and reopen the map instead only toggled it shut (Q lost, M closed it). Start every `keys` with `wait 1500ms;` and check the map with `pos` (`menu 0x100` = open, `0x0` = closed). The map stays open while the other window has the focus, is not redrawn while open (reopen it for a photo), opens only with a held `M 300ms`, and a pin needs the middle button (`mclick`).
- **The map's pin sync runs only when the marker records change**: forcing `rivalhud 0` does not bring a hidden rival pin back until its owner moves it (and `rivalhud auto` leaves an already listed pin until then).
- **An attack aims where the camera looks, not where the character faces** (2026-10-28, RW-8): `mob_go` writes the character heading, but the game turns the character to the camera on the next attack, so a click swings at the camera's view. After a teleport the camera keeps its old azimuth (the enemy can be behind the camera) and, if the start hawk ride has not ended, the position writes snap back and no attack lands. Use the test aid `mob_kill` for a deterministic kill; to aim for real, turn the camera (`nro keys` supports `mousemove dx dy`) or lock on, and wait until the ride is over.
- **The desktop can go to sleep during a run** (2026-10-28): with the display off, `nro shot` reports "the picture is black" and a click/key step may land nowhere. Keep `scripts\keep-display-on.ps1` running **and** set the Windows timeouts to never (`powercfg /change monitor-timeout-ac 0`, `standby-timeout-ac 0`); a synthetic mouse move wakes the monitor but does not replay the lost step.
